# Шаблон тест-кейса

Один тест-кейс = одна карточка = обычно один критерий приёмки (`AC-XX`) из раздела 10.1
какого-то ТЗ, либо один уже известный дефект/регрессия, не покрытые ни одним `AC` (пример —
регресс-чеклист в `tz-100-test-cases.md`, карточки `TC-ТЗ<NNN>-R<NN>` — тот же шаблон, префикс
`R` в номере просто отличает их на глаз от карточек по AC). Карточки одного ТЗ живут в одном
файле `references/tz-NNN-test-cases.md`. Новую карточку можно завести со статусом
«не запускался» и пустым «Фактическим результатом» — это честное стартовое состояние, а не
брак. Но статусы **✅ проходит**, **⚠️ известное отклонение** и **❌ не реализовано** — только
по итогам реального прогона (живого через MCP или уже задокументированного в разделе 16 самого
ТЗ), а не предсказанием «должно сработать».

**Тип «авто» сюда не заводится вообще** — критерии этого типа уже покрыты
`tools/run_tests.gd` (`T-NN`), дублировать их отдельной карточкой в этом каталоге незачем;
если по ходу работы обнаружился такой критерий без карточки — оставь короткую
перекрёстную ссылку на `T-NN` вместо полной карточки (см. пример в `tz-100-test-cases.md`,
где номер `R4` пропущен как отдельная карточка ровно по этой причине).

Копируй блок ниже целиком для каждого нового теста.

---

### TC-ТЗ<NNN>-<NN> — <короткое название на русском>

| Поле | Значение |
|---|---|
| Источник | ТЗ-NNN, `AC-XX` (`FR-YY`) — или «регрессия, не в AC» |
| Тип | рантайм-авто \| визуально \| вручную |
| Сцена | `scenes/.../имя.tscn` |
| Статус | не запускался \| ✅ проходит \| ⚠️ известное отклонение \| ❌ не реализовано |
| Дата последнего прогона | ГГГГ-ММ-ДД |

**Предусловия** — что должно быть верно до первого шага: какая сцена запущена, в каком
модуле/состоянии должен быть игрок, что должно быть true/false у зависимостей теста.

**Шаги**
1. Конкретный вызов MCP-инструмента или GDScript-сниппет для `run_script` — не описание
   намерения («подойти к панели»), а то, что реально выполняется.
2. …

**Ожидаемый результат** — что именно должно получиться: конкретное число с допуском,
булево значение, содержимое скриншота. Не «должно работать корректно» — то же самое,
что требует раздел 4 ТЗ.

**Фактический результат** — что получилось при последнем прогоне. Пусто, пока тест ни разу
не запускался.

**Чек-лист прогона**
- [ ] Перед стартом проверено, что не висит Godot от предыдущего запуска
      (`Get-Process -Name Godot`), либо `stop_project` предыдущей сессии выполнен
- [ ] Сразу после `run_project` проверен `get_debug_output` — ошибок парсинга/падений нет
- [ ] Если объект-цель — потомок вращающегося/движущегося узла (`RotatingRing` и т.п.):
      сравнение позиций через `position`/`to_local()`, не через `global_position`
- [ ] Нестандартные типы возврата в `run_script` — явно типизированы (`var x: Vector2 = ...`)
- [ ] Если тип теста «визуально» — снят `take_screenshot` и результат сверен глазами
- [ ] Сессия завершена `stop_project`, даже если тест провалился
- [ ] Фактический результат сверен с ожидаемым; при расхождении, которое ещё не задокументировано
      как известное отклонение — сообщено пользователю, а не тихо помечено ⚠️ или ✅
- [ ] Поля «Фактический результат», «Статус», «Дата последнего прогона» обновлены в файле
      карточки на диске (не только в ответе пользователю)
